# 点击演示 App：个人 iPhone 安装指南

更新日期：2026-09-24

## 1. 先确认你下载的是什么

本次已生成的是 **SwiftUI 原生 iOS 源码工程**。开发电脑是 Windows，没有 Xcode/iOS SDK，也没有你的苹果签名配置，所以目前没有生成可安装的 IPA，也没有进行真机运行验证。

`TapHello-iOS-Source.zip` 是源码压缩包，不是安装包。百度网盘用于传递文件，不会替 App 完成编译或签名。iPhone 无法像安装 Android APK 一样，点击普通网盘里的 ZIP 或未签名 IPA 完成安装。

| 文件/方式 | 用途 |
| --- | --- |
| `TapHello.xcodeproj` | 在 Mac 上用 Xcode 打开、编译和签名 |
| 源码 `.zip` | 保存和传递项目，不能直接安装 |
| 模拟器 `.app` | 仅用于 Mac 上的 iOS 模拟器，不能安装到 iPhone |
| 为你的设备签名的 `.ipa` | 通过符合签名要求的安装方式装到对应设备 |
| TestFlight | 使用开发者上传并处理完成的测试版本；本项目目前没有 TestFlight 邀请 |

## 2. 推荐方式：Mac + 普通 Apple 账号 + 自己的 iPhone

个人学习和真机测试可以使用普通 Apple 账号的 Personal Team，不必先购买付费开发者会员。Apple 当前说明：免费配置描述文件有效期为 7 天，过期后需要重新构建、安装；同一设备最多可安装 3 个此类测试 App。它不适合“一次安装永久使用”。

准备：

- 一台能运行合适版本 Xcode 的 Mac。Xcode 版本需支持你的 macOS 和 iPhone 系统，参见下方官方兼容表。
- 一部 iOS 16.0 或以上的 iPhone，以及数据线。
- 你的 Apple 账号。账号登录、验证码和设备确认由你自己在苹果界面完成。
- 首次下载 Xcode、iOS 平台组件和配置签名时需要网络；App 运行本身不需要网络。

### 第一步：解压并打开工程

在 Mac 上下载并解压 `TapHello-iOS-Source.zip`，进入 `ios` 目录，双击 `TapHello.xcodeproj`。不要只打开某个 `.swift` 文件。

首次启动 Xcode 时，按界面提示完成组件安装。在 Xcode 设置里下载 iOS 平台/模拟器支持；入口名称可能因版本显示为 Components 或 Platforms。

### 第二步：登录 Apple 账号

打开 Xcode → Settings → Apple Accounts（旧版可能叫 Accounts），添加自己的 Apple 账号。

### 第三步：设置签名

1. 点击左侧蓝色工程图标 `TapHello`。
2. 在 TARGETS 中选择 `TapHello`，打开 **Signing & Capabilities**。
3. 保持 **Automatically manage signing** 勾选。
4. 在 **Team** 中选择自己的 Personal Team 或付费开发者 Team。
5. 将 **Bundle Identifier** 从 `com.example.taphello` 改成唯一值，例如 `com.yourname.taphello.demo20260924`，其中 `yourname` 换成你自己的字母标识。
6. 如果提示标识已被占用，换一个唯一后缀，等待 Xcode 完成签名配置。

### 第四步：连接 iPhone

使用数据线连接 Mac 和 iPhone，解锁手机，并按手机提示确认信任此电脑。

从 Xcode 顶部运行目标中选择你的实际 iPhone，不要选择模拟器或 Any iOS Device。

若 Xcode 提示需要 Developer Mode，由你在 iPhone 的“设置 → 隐私与安全性 → 开发者模式”中开启，并按提示重启和确认。此选项可能要在与 Xcode 发起配对后才出现。

若设备系统太新而 Xcode 不支持，先按官方兼容表更新 Xcode/平台支持；不需要改源码。

### 第五步：运行并安装

点击 Xcode 左上角 Run（三角形），或按 **⌘R**。Xcode 会编译、签名、安装并启动 App。

若手机提示开发者尚未受信任，按设备给出的路径，在“设置 → 通用 → VPN 与设备管理”中找到你自己的开发者身份，按提示确认。没有出现此提示就无需额外操作。

成功后，桌面会出现名为 **“点击演示”** 的 App。首次完成安装后，结束 Xcode 调试并拔掉数据线，再从手机桌面点击图标，确认可以独立打开。

### 第六步：验证功能

1. 打开 App，看到“我的第一个 iPhone App”和“点我显示文字”按钮。
2. 点击按钮，看到“你好，iPhone！你已经成功点击了按钮。”
3. 再次点击，消息保持显示。
4. 结束 App 进程后重新打开，回到初始提示。这是正常行为，因为本示例不保存状态。
5. 断开网络再试一次，按钮仍应正常工作。

免费签名过期后：重新连接 Mac，用同一 Apple 账号、同一 Bundle Identifier，再按 ⌘R 安装。

## 3. 已有付费开发者账号，想要可传递的 IPA

这种方式仍需要 Mac/Xcode 完成编译与签名；付费账号本身不会把 Windows 变成 iOS 构建环境。

1. 在 Xcode 中完成上面的 Team 和 Bundle Identifier 配置。
2. 通过 Xcode 或开发者后台把目标 iPhone 注册到对应开发者 Team。
3. 在顶部选择适合归档的 iOS 真机目标，执行 **Product → Archive**。
4. 归档成功后，在 Organizer 中选择 **Distribute App**，选择适用于已注册设备的分发方式（不同版本可能显示 Release Testing、Ad Hoc 或相近名称），按向导导出签名 IPA。
5. 确认描述文件包含目标 iPhone，使用 Xcode 的设备管理界面或 Apple Configurator 安装到该手机。

导出的 IPA 只对签名允许的设备和有效期有效；不是所有 iPhone 都能安装的通用文件。普通免费 Personal Team 用户优先使用前一节的 Xcode 直接运行方式，不应把 Ad Hoc 导出当作免费账号通用能力。

如希望让手机通过链接安装，可考虑付费开发者账号的 TestFlight 测试分发；这需要配置 App Store Connect、上传构建并完成相应处理/审核，并不是百度网盘直接安装。

## 4. 只有 Windows / 只有 iPhone 怎么办

当前工程需要先获得一个 Mac 构建与签名环境。可以使用自己已有或可借用的 Mac；远程 Mac 的编译、签名和设备安装方式需要另行配置，不能假定本地 USB 手机会自动连接到远程 Mac。

如果你只需要桌面图标和一个按钮，也可以另做一个能添加到 iPhone 主屏幕的 Web App。那是另一种交付形式，需要可访问的网页地址，不是本目录的原生 iOS App，也不是把源码 ZIP 改名就能完成。

## 5. 常见问题

| 提示/现象 | 处理方式 |
| --- | --- |
| Signing requires a development team | 在 Signing & Capabilities 选择自己的 Team |
| Bundle identifier is not available | 修改为自己独有的 Bundle Identifier |
| No profiles for… | 确认账号已登录、自动签名已开启、手机已被识别且网络正常 |
| Developer Mode disabled | 在手机上按 Xcode 提示完成开发者模式设置 |
| 找不到自己的 iPhone | 检查数据线、解锁、信任及 Xcode 与手机系统兼容性 |
| 模拟器提示缺少 Runtime | 在 Xcode 设置中下载对应的 iOS Simulator Runtime |
| 几天后 App 打不开 | 免费签名可能已到期，连接 Mac 重新运行安装 |
| 网盘下载后没有“安装”按钮 | 下载的是源码；或者 IPA 仍需匹配签名和安装工具 |
